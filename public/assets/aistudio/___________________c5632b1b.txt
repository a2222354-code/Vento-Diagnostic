## 1. Архитектура приложения

| Слой | Где | Что делает |
|---|---|---|
| UI | Kotlin + Jetpack Compose, `com.example.kwp1281.MainActivity` / `MainViewModel` | Экраны, выбор ЭБУ, отображение данных |
| Repository | `data/kwp1281/Kwp1281Repository` | Логика сценариев: определение скорости, повторы, диагностика ошибок |
| JNI-коннектор | `data/kwp1281/Kwp1281NativeConnector` | Тонкая обёртка над нативными функциями |
| Нативная библиотека | `lib/arm64-v8a/libkwp1281.so` (C++), класс `Kwp1281Protocol` | **Весь протокол**: тайминги, 5-baud init, блоки, keep-alive |
| Железо | `FtdiWrapper` + FTDI D2XX (`com.ftdi.j2xx`) | Доступ к адаптеру через D2XX, не через стандартный Android USB-serial |

Пакет: `com.klinediagnostic.kwp1281.demo`. Разрешения: только INTERNET и сервисные (аналитика/реклама). Bluetooth/USB-разрешений в манифесте нет — USB идёт через D2XX.

### Поддерживаемое железо **[подтверждено]**
- Адаптеры на FTDI (VID `0x0403`: FT232R `6001`, `6014`, `6015` и т.п.) — поддерживаются.
- CH340 (`1A86:7523`), PL2303 (`067B:2303`), CP210x (`10C4:EA60`) — в коде помечены как **не поддерживаемые**.
- Причина: приложению нужен точный контроль линии TX (bit-bang) для медленной инициализации и затем UART.
- Опционально поддерживается управление L-line («L-LINE INIT ASSIST»); если у адаптера нет отдельной линии, пишет `UNSUPPORTED`.

Колбэки в нативный код (через JNI в `FtdiWrapper`): `setPinState(bool)`, `setBitBangMode()`, `setUartMode(baud)`, `purgeBuffers()`, `readData(buf, n, timeoutMs)`, `writeData(buf, n)`, `getQueueStatus()`, `setLatencyTimer`, `resetDevice`.

## 2. Физика и режимы линии

- Шина K-Line (ISO 9141 / KWP1281), полудуплекс по одному проводу, уровни 12 В на стороне адаптера.
- В кабелях KKL на FTDI **собственные переданные байты возвращаются в RX (эхо)**. Нативный код это учитывает: функция `isEchoOrComplement()` принимает байт, если он равен либо отправленному (эхо), либо его побитовой инверсии (ответ ЭБУ). Всё остальное считается ошибкой `Unerwartete Antwort 0x%02X (weder Echo ... noch Komplement ...)`.
- Два режима работы адаптера:
  1. **Bit-bang** (`setBitBangMode`) — программное управление уровнем TX для медленной инициализации.
  2. **UART** (`setUartMode(baud)`) — обычный обмен 8N1 после инициализации.

## 3. Последовательность подключения

### 3.1 Выбор скорости и адреса **[подтверждено]**
- Значения по умолчанию в `startFullInit`: адрес `23` (`0x17`, панель приборов), скорость `10400`.
- `defaultBaudrateForEcu(addr)`: для адресов `0x01`, `0x15`, `0x17` > **10400**, для остальных > **9600**.
- Есть автоопределение (`detectBaudrate`): перебирает варианты скорости с паузой между попытками, логирует `FailureStage` и трассу (`InitTrace`) для каждой.
- Вызов: `nativeFullInit(ecuAddr, baudRate, compatibilityMode, lLineEnabled, lLineMode, lLinePulseMs, lLineSettleMs)`.

Адреса, встречающиеся в коде: `0x01` (двигатель), `0x03` (ABS), `0x15` (подушки безопасности), `0x17` (приборная панель). Это стандартная VAG-адресация **[стандарт]**.

### 3.2 5-baud инициализация (`Kwp1281Protocol::perform5BaudInit(addr)`) **[подтверждено по дизассемблеру]**

Адрес ЭБУ передаётся на 5 бит/с в формате 7O1 (7 бит данных, нечётная чётность). Линия выставляется вручную колбэком `setPinState`, каждый бит держится **200 мс**.

```
1. Перевести адаптер в bit-bang, TX = HIGH (idle).
2. Пауза перед стартом: ~250 мс (248 мс по таймеру) для ряда ЭБУ, иначе ~200 мс.
3. Старт-бит: TX = LOW, 200 мс.
4. 7 бит адреса, младший бит первым (LSB first), по 200 мс каждый.
   Для каждого бита счётчик: parity ^= bit.
5. Бит чётности: TX = !(parity)  > нечётная чётность (odd), 200 мс.
6. Стоп-бит: TX = HIGH, 200 мс.
7. Дополнительная пауза после стопа: 20 мс; для адреса 0x17 — 30 мс.
8. Далее переключение в UART и ожидание ответа ЭБУ.
```

Тайминг бита реализован через **абсолютный дедлайн** (`start + 200 ms`, цикл ожидания шагами 50 мкс), а не сумму `sleep`, чтобы ошибка не накапливалась. Это важно для точности: допуск на 5 бод у ЭБУ невелик.

Пример: адрес `0x17` = `0010111b`. Биты LSB-first: `1,1,1,0,1,0,0`; единиц 4 > чётное число > бит чётности = 1.

### 3.3 Рукопожатие (`sumHandshake`) **[подтверждено + стандарт]**

После перехода в UART (8N1, 9600 или 10400):

1. Ждать от ЭБУ **sync-байт `0x55`** (таймаут до 5000 мс; посторонние байты отбрасываются, в логе `Unerwartetes Byte 0x%02X statt 0x55 (verworfen)`).
2. Принять **keyword low** (KW1), затем **keyword high** (KW2). Таймауты на байты ключевых слов зависят от режима: порядка 150–900 мс (в коде значения `0x96…0x384`).
3. Отправить ЭБУ **инверсию keyword** (`~KW2`, «complement»). Время выдачи инверсии тоже регулируется таймингом (`[TIMING] kwL ... complement TX`), есть расширенный режим «TSMODUS» с увеличенными таймаутами.
4. ЭБУ присылает первый блок идентификации (ASCII номер детали и т.п.).
5. Тестер отвечает ACK-блоком; в логе `Fehler beim Senden des ACK nach dem ersten Initialisierungsblock` в случае сбоя.

Классические значения keyword для KWP1281: `0x01 0x8A` (KW = 0x8A01 …), но приложение значения не жёстко проверяет, а возвращает инверсию **[стандарт]**.

Особые случаи, найденные в коде:
- **Compat Mode** — режим совместимости с дополнительной задержкой (35 мс) в сторону ЭБУ.
- **Airbag (0x15)** — «AIRBAG SAFE POLICY»: для этого ЭБУ Compat Mode отключается, повторов нет, задержка ? 35 мс. Если не получилось, делается один fallback без Compat Mode.
- Отдельный **L-line assist**: перед bit-bang можно подать импульс на L-line (`lLinePulseMs`, `lLineSettleMs`), если адаптер умеет.

## 4. Формат блока KWP1281 **[подтверждено + стандарт]**

```
+--------+---------+-------+----------------+--------+
| Length | Counter | Title | Data (0..N)    | 0x03   |
+--------+---------+-------+----------------+--------+
```

- `Length` — число байт после себя **без** конечного `0x03` (то есть `Counter + Title + Data`).
- `Counter` — сквозной счётчик блоков, общий для обеих сторон; каждый блок `+1` (с переходом через 0xFF > 0x00). Тестер сбрасывает/выставляет его при инициализации (`resetBlockCounter`). В коде есть контроль регрессии: `Blockzahler-Regression: Empfangen 0x%02X, erwartet 0x%02X`.
- `Title` — тип блока / команда.
- `0x03` — конец блока; **не подтверждается инверсией**.

### 4.1 Побайтовое подтверждение (самое важное)

Каждый байт блока, кроме последнего `0x03`, подтверждается получателем **инверсией** (`~byte`, т.е. `0xFF ^ byte`):

```
sendBlock(block):
    for byte in block[:-1]:                # всё кроме 0x03
        write(byte)
        rx = read(timeout=300 ms)          # 0x12C
        # эхо собственного байта (KKL) отбросить, затем ждать ответ
        if rx != (~byte & 0xFF): retry (до 4 попыток) / ошибка
        sleep ~3 ms                        # пауза между байтами
    write(0x03)                            # без подтверждения
    sleep ~5–8 ms                          # межблочная пауза
```

Приём блока ЭБУ зеркален: тестер читает байт и сразу отвечает `~byte`; после `0x03` ничего не отправляет.
В коде есть ограничения: блок не больше `0x20` (32) байт, минимальная длина — 3.

Значения таймингов, найденные в `sendBlock`/`readBlock` (наносекунды в константах): 8 мс, 5 мс, 3 мс, 2 мс — паузы между отправкой/приёмом байтов и блоков; тайм-аут на ответ — 300 мс.

### 4.2 Типы блоков (title)

Подтверждённые в бинарнике:
| Title | Смысл |
|---|---|
| `0xF6` | ASCII-блок идентификации (номер детали, название, VIN/кодирование) |
| `0xE7` | Ответ с измерительным блоком (4 значения: формула + 2 байта) |
| `0xA0` | Отказ при чтении памяти («недоступный диапазон») |
| `0x10` | Ответ с кодировкой (coding) |
| `0x2B`, `0x1B` | Команды логина (стандартный VAG / VDO). Подробности работы с ними намеренно не раскрываются |

По публичной спецификации KWP1281 **[стандарт]**, общие команды:
| Title | Смысл |
|---|---|
| `0x09` | ACK / «нечего передавать» (используется как keep-alive) |
| `0x0A` | NAK / отказ |
| `0x06` | Завершение сеанса (End Output) |
| `0x00` | Запрос идентификации |
| `0x05` | Стереть коды неисправностей |
| `0x07` | Прочитать коды неисправностей (ответ `0xFC`) |
| `0x08` | Прочитать группу измерений (ответ `0xE7`) |
| `0x28` | Базовая настройка (Basic Setting) |
| `0x03` | Чтение памяти (ROM/RAM/EEPROM — разные команды у разных ЭБУ) |

Формат измерительного значения в блоке `0xE7`: тройки `[формула][A][B]`, по четыре в блоке; приложение содержит таблицу формул (`Unbekannte Formel: 0x%02X`) и пересчёт единиц (метрика/имперская).

## 5. Сессия: keep-alive и конкурентность **[подтверждено]**

- ЭБУ завершает сеанс, если долго нет обмена (порядка секунды). Поэтому есть **keep-alive поток**: пока нет рабочих команд, он отправляет блок ACK (`0x09`) и читает ответ.
- Перед любой командой keep-alive приостанавливается (`nativePauseKeepAliveAndWaitForConfirmation`), после команды возобновляется. Доступ к линии защищён мьютексом (`g_keepAliveMutex`), есть счётчики ошибок и аварийный перезапуск потока.
- Циклическое чтение измерений (`startCyclicMeasuringBlock`) работает отдельным worker-потоком, интервал по умолчанию 500 мс.
- Есть восстановление связи (`recoverCommunication`), «адаптивная очистка буферов» (`adaptiveBufferCleanup`) и трасса инициализации (`InitTrace` с этапами `INIT_START`, `AFTER_5BAUD`, `FAIL_UART_SWITCH`, `FAIL_KEYWORD_L_TIMEOUT` и т.д.).

## 6. Типовой сценарий «прочитать неисправности»

```
1. 5-baud init(addr)                         # адрес ЭБУ на 5 бод
2. UART 9600/10400 8N1
3. 0x55, KW1, KW2  <-  ECU ;  ~KW2  ->  ECU
4. ECU шлёт блоки идентификации (0xF6 …) по одному; на каждый тестер отвечает 0x09 (ACK)
5. Тестер: блок [len=3][cnt][0x07][0x03]        # читать DTC
6. ECU:    блок title=0xFC, тройки [код_hi][код_lo][статус] … , либо 0x09 если ошибок нет
7. Тестер: блок 0x09 (keep-alive) периодически
8. Тестер: блок 0x06 (конец)                    # завершение сеанса
```
